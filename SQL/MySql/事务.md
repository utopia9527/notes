- 在事务嵌套是，注意Mysql 的隐式提交
  - **在MySQL中，第二个`START TRANSACTION`会隐式提交第一个事务**
  - 如果只有一个 start transacttion(关闭自动提交)，那么当commit 之后事务已经被提交，其余的将自动恢复自动提交

```mysql
// ---------------------错误/不清晰的写法---------------------------



----------------------------------------------------------------------------------------

情况一：
-- 第一步：开始第一个事务
START TRANSACTION;  -- 事务A开始
INSERT INTO t1 VALUES (1);  -- 操作1

-- 第二步：第二个START TRANSACTION
START TRANSACTION;  -- 这会隐式提交事务A，然后开始事务B
/*
MySQL的实际行为：
1. 隐式执行 COMMIT 提交事务A
2. 然后开始一个新的事务B
*/

-- 第三步：在事务B中操作
INSERT INTO t2 VALUES (2);  -- 操作2，属于事务B

-- 第四步：回滚事务B
ROLLBACK;  -- 只回滚事务B

----------------------------------------------------------------------------------------

情况二：

1. START TRANSACTION        → 开始事务A，设置 autocommit=0（临时）
2. INSERT INTO t1 VALUES(1) → 属于事务A

3. COMMIT                   → 提交事务A，恢复 autocommit=1  <========> 注意这里是重点

4. INSERT INTO t2 VALUES(2) → 自动开始并提交事务B（因为 autocommit=1）

5. COMMIT                   → 错误 && 没有事务在运行！

====================================================

注意: 对于2来说，在实际代码中(c++) 并不会自动恢复自动提交事务（命令行默认回复，代码不是）
```
