```bash
大对象分配依赖 mmap，但释放后内存未必立即归还给系统
对于超过阈值（如 glibc 默认为 128KB）的大对象，malloc 会直接使用 mmap 分配独立内存块。
释放时（free），ptmalloc 会调用 munmap 归还给系统，但存在两个问题：
若释放的内存块不是页对齐的完整页（如 2.1G 可能包含非整数页的内碎片），munmap 可能无法完全释放，导致部分内存滞留。
频繁 mmap/munmap 会在虚拟地址空间留下 “空洞”，后续分配 2.0G 时，系统可能因虚拟地址不连续而不得不分配新的物理页，而非复用之前释放的 2.2G 内存。
物理内存碎片与 “不可复用” 问题
虽然 mmap 分配的是独立区域，但物理内存可能因频繁分配 / 释放变得碎片化。
例如：先分配 2.1G（占用物理页 A）、2.2G（物理页 B），释放 2.2G 后，物理页 B 理论上可复用，但由于新分配的 2.0G 大小与 B 不完全匹配（或虚拟地址映射限制），系统可能优先分配新的物理页 C，导致 A（2.1G）+ C（2.0G）= 4.1G，但加上未完全回收的碎片，总物理内存达到 6.3G。

```
